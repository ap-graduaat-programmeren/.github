# Welkom bij AP Graduaat Programmeren

Deze GitHub-organisatie is de gezamenlijke werkruimte voor het graduaat Programmeren aan AP. Je vindt hier repositories met lesmateriaal, oefeningen en projecten. Als lid werk je samen in projecten en krijg je toegang tot repositories via teams.

## Zo werkt toegang

- Wat je kunt zien en aanpassen hangt af van de zichtbaarheid van een repository en de rechten van de teams waarvan je lid bent. Lid zijn van de organisatie geeft dus niet automatisch toegang tot elke repository.
- Rechten op repositories worden via teams beheerd. Geef geen individuele leden rechtstreeks toegang tot een repository; voeg hen toe aan het passende team.
- Kies per team de rol die nodig is voor het werk. Geef teams niet meer rechten dan nodig.

## Teams voor projecten

Maak voor een groepsproject een team aan en voeg de projectleden eraan toe. Geef daarna het team toegang tot de repositories van het project. Zo beheer je de toegang en rol op één plek: teamleden krijgen de rechten die aan hun team zijn toegekend.

GitHub biedt onder meer deze repositoryrollen:

- **Read:** repositories bekijken en ophalen.
- **Triage:** issues en pull requests beheren, zonder code te kunnen pushen.
- **Write:** bijdragen aan code en wijzigingen pushen.
- **Maintain:** de repository beheren zonder alle gevoelige beheerrechten.
- **Admin:** volledige controle over de repository en de instellingen.

Gebruik voor gewone projectbijdragen doorgaans `Write`; reserveer `Admin` voor wie de repository-instellingen en toegang moet beheren.

## Organisatie-owners

Owners beheren de organisatie en kunnen helpen met organisatiebrede instellingen of toegangsproblemen. Je vindt de actuele owners in het [People-overzicht van de organisatie](https://github.com/orgs/ap-graduaat-programmeren/people).

## Bijdragen aan een repository

1. **Zoek de juiste repository.** Kies de repository die bij je vak, opdracht of project hoort. De README van die repository vertelt wat erin staat en hoe je ermee aan de slag gaat.
2. **Lees de lokale afspraken.** Controleer vóór je begint de README en eventuele bestanden zoals `CONTRIBUTING.md`. Opdrachten kunnen eigen instructies, deadlines en afspraken hebben; die gaan voor op deze algemene handleiding.
3. **Werk vanuit je eigen kopie of branch.** Maak een fork of een nieuwe branch, afhankelijk van de instructies van de repository. Pas bestanden daar aan en commit je wijzigingen met een duidelijke beschrijving.
4. **Deel je bijdrage.** Open een pull request als je wijzigingen wilt laten nakijken of samenvoegen. Beschrijf wat je hebt aangepast en verwijs zo nodig naar de bijbehorende opdracht of issue.

## Problemen of vragen?

- Kijk eerst of de README, opdrachtinstructies of bestaande issues je vraag beantwoorden.
- Gebruik Issues voor een concrete foutmelding, verbetering of vraag over een repository. Vermeld welke repository het betreft en hoe iemand het probleem kan reproduceren. Deel geen wachtwoorden, tokens of andere geheime gegevens.
- Weet je niet waar je vraag thuishoort of heb je toegang nodig? Neem contact op met je docent, het team van het project of een organisatie-owner.

## Goed om te weten

- Volg altijd de instructies in de repository waaraan je werkt; deze kunnen per vak of project verschillen.
- Bewaar persoonlijke gegevens, wachtwoorden, API-sleutels en andere vertrouwelijke informatie niet in code, issues of pull requests.
- Controleer vóór je een wijziging deelt dat je de juiste bestanden hebt aangepast en dat je opdracht of project nog werkt.
